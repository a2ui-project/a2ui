Inference Formats

An inference format defines the structured notation that a language model reads in its system prompt and writes in its response before the server compiles that output into standard A2UI wire messages. Because compilation happens on the server, every client renderer receives the same A2UI JSON over the wire regardless of how the model produced it.

In the diagram below, A2uiRequestProcessor coordinates three server-side stages. First, PromptGenerator turns the negotiated catalog schemas, instructions, and few-shot examples into a format-specific prompt snippet. Next, the model writes UI blocks inside sentinel tags (<a2ui>...</a2ui> for Express or <a2ui-json>...</a2ui-json> for Direct JSON) alongside conversational prose. Finally, Parser or ResponseStream heals streaming chunks, compiles each block into wire JSON, and validates every message against RendererState.

Wire protocol vs. generation formats

Standard JSON is well suited as a wire protocol between an agent server and a client renderer: it is self-describing, language-independent, and validated directly by JSON Schema. Asking a language model to emit raw wire JSON token by token, however, carries avoidable costs:

  1. Repeated keys ("id", "component", "@path") and hand-written component identifiers make raw wire JSON roughly three times longer than positional constructor calls.
  2. Embedding full JSON Schemas in the system prompt consumes roughly twice as many input tokens as compact component signatures.
  3. Deeply nested braces, quotes, and manual component IDs increase syntax and reference errors, especially on smaller, faster models.

Inference formats separate what is best for the model to generate from what is best for the renderer to consume. The Agent SDKs include two built-in formats and allow custom implementations:

FormatSentinel tagsSDK supportHow it represents UI
Express<a2ui>...</a2ui>TypeScript, Python, Dart (default)Compact positional DSL with nested component calls and $/path data assignments, compiled to flat wire JSON.

Not every A2UI agent uses free-form model generation. Regulated or deterministic workflows can also construct wire messages directly in server code (driven by a classifier, state machine, or macro) and send the resulting JSON to the renderer without an LLM compilation step.

How inference formats stay swappable

Swapping an inference format requires no changes to catalogs, few-shot examples, or client renderers because every format in the Agent SDK shares three design properties:

  1. Catalog-agnostic prompt synthesis: Rather than hardcoding component names, a format’s PromptGenerator inspects the negotiated Catalog schemas at runtime to derive component signatures, function signatures, and dynamic binding rules.
  2. Bidirectional translation (compile and decompile): Alongside compiling model output into wire messages, each format’s Parser can decompile wire messages back into the format’s text notation. Structured few-shot examples, fenced json message blocks inside a catalog’s instructions, and prior conversation turns can therefore be authored once as wire messages and rendered automatically in whichever format is active.
  3. Incremental stream compilation and validation: Both one-shot parsing (parseResponse / parse_response) and chunked streaming (openStream / open_stream) separate conversational text from UI sentinel blocks, heal in-progress string literals on configured progressiveKeys (such as "text"), emit incremental wire deltas as statements arrive, and validate every message against RendererState so malformed output can be returned to the model for self-correction.

In the Agent SDKs (available for TypeScript, Python, and Dart; the Swift and Kotlin packages focus on client-side rendering), A2uiGenerator defaults to ExpressFormatFactory and accepts any InferenceFormatFactory globally or per request while keeping prompt generation and response parsing identical:

  • Python

Express covers v0.9, v0.9.1, and v1.0 generation with lower token cost, while Direct JSON remains useful when serving legacy v0.8 payloads in Python, debugging raw wire payloads, or calling a model fine-tuned directly on A2UI JSON schemas. Teams experimenting with alternative grammars (such as HTML-inspired or S-expression notations; see python/a2ui_agent/src/a2ui/inference_formats/experimental/) implement the same InferenceFormatFactory, PromptGenerator, and Parser interfaces.
