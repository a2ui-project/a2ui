Call MCP Tools from A2UI

The @a2ui/catalog-mcp package connects A2UI v1.0 or later web surfaces directly to Model Context Protocol (MCP) servers so buttons, inputs, and surface actions can call MCP tools and write their JSON or text results straight into the surface Data Model without waiting for another round-trip to the agent.

Looking for another MCP pattern?

See the MCP Integration Overview to compare calling headless MCP tools with serving reusable a2ui:// layouts (Serve A2UI Layouts from an MCP Server), embedding sandboxed ui:// HTML apps (Embed MCP Apps in A2UI Surfaces), or bundling A2UI inside an MCP App (Render A2UI Inside an MCP App).

Quick setup

Setting up @a2ui/catalog-mcp takes three steps.

Install the packages

Install @a2ui/catalog-mcp alongside @a2ui/web_core, lit, and the MCP TypeScript SDK:

@a2ui/web_core and lit are peer dependencies so your renderer and catalog share one copy of A2UI’s core classes, and @modelcontextprotocol/sdk provides the MCP Client that connects to your server.

Register the catalog in your app

Connect an MCP Client to your server, pass mcpCatalog alongside basicCatalog (or your own component catalog) to MessageProcessor, and call configureMcpCatalog:

  • Lit
  • React
  • Angular

getMcpClientForTool receives the name of the tool being called and returns the MCP client that executes it. When your app connects to one MCP server, return that client for every call; for multiple servers, see Advanced configuration and troubleshooting.

Share the catalog schema with your agent

Include the MCP catalog schema in your agent setup so it knows how to emit MCP tool calls and McpApp components:

  1. Load @a2ui/catalog-mcp/catalog.json (or catalogs/mcp/v1/catalog.json on non-Node backends) alongside your component catalog when building your agent’s prompt and schema validator.
  2. Advertise the MCP catalog ID (https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json, exported as mcpCatalog.id and MCP_CATALOG_ID) in supportedCatalogIds. Calling processor.getRendererCapabilities({versions: ['1.0']}) includes every registered catalog automatically.

You are ready to call MCP tools from your UI. If you also embed McpApp HTML widgets, complete the extra sandbox file step in Embed MCP Apps in A2UI Surfaces.

Calling MCP tools from your UI

An A2UI component can invoke an MCP tool when a user clicks a button or types into a field. Because the browser calls your MCP server through callMcpTool, the surface updates right away without another agent turn.

Store tool output at a data path

The easiest way to call a tool is to pass targetDataPath. When the tool finishes, callMcpTool writes the response object to that path in the surface data model so your components can bind to it directly.

Components on the same surface ("version": "1.0") can then bind to /issueResponse/structuredContent/issues (when the server returns structured content), /issueResponse/json (when the tool returns JSON text), or /issueResponse/text (for plain text).

Response object fields, error handling, and rapid-input protection

callMcpTool writes (and returns) an object with these fields:

FieldContents
structuredContentStructured data object returned by the MCP server, when the server includes one.
jsonParsed JSON value when text is a JSON object or array (or an array of parsed JSON blocks when the tool returns several text blocks).
textAll text content blocks from the tool result, joined with \n.
toolNameName of the tool that ran.
toolInputResolved arguments sent to the tool.
toolResultRaw MCP CallToolResult from the server.

If a tool call fails or returns isError: true, callMcpTool throws an A2uiExpressionError and leaves the data model unchanged.

When several calls write to the same targetDataPath concurrently (such as a search box calling a tool as the user types), only the latest call writes its result. Slower responses from earlier calls are ignored so stale results never overwrite newer ones. Give each independent UI feature its own targetDataPath so unrelated calls do not cancel each other’s writes.

Filter and reshape JSON results

When an MCP tool returns more fields or rows than your UI needs, chain callMcpTool with transformData (a JMESPath query) and updateDataModel:

Reading from the innermost call outward:

  1. callMcpTool runs list_issues and returns the response object containing json.
  2. transformData keeps only open issues, selects {number, title}, and wraps the result in {"/issues": [...]}.
  3. updateDataModel writes /issues into the surface data model, updating any components bound to /issues.

Note that the rapid-input guard only applies to targetDataPath on callMcpTool, not to updateDataModel. For inputs that fire on every keystroke, bind directly to targetDataPath.

Parse plain-text tool output

Some MCP servers return plain text meant for a language model (such as Title: ...\nURL: ... blocks) rather than JSON. The catalog includes split and regexCapture so an A2UI payload can extract rows and fields before passing them to transformData and updateDataModel, without adding per-tool parsing code to your host app. Your host app still chooses which MCP servers to connect through getMcpClientForTool (see Quick setup). These built-in functions are most useful when users or admins configure that server list at runtime, such as in a chat app or playground. If your app only connects to one or two MCP servers that you control, writing a custom function in your own catalog is usually simpler (see Add your own data-parsing functions under Advanced configuration and troubleshooting).

Here are the four data functions in @a2ui/catalog-mcp:

FunctionArgumentsWhat it does
transformDatajmespath, dataEvaluates a standard JMESPath query against data (returning null for missing fields).
updateDataModelupdatesWrites each {path: value} pair in updates to the surface data model (/ keys are absolute; others resolve relative to context).
splitvalue, separatorSplits a string (or each item in an array of strings) by separator, or into individual characters when separator is "".
regexCapturevalue, patternReturns capture groups from the first match of pattern (or null if unmatched) for a string or each string in an array.

Tools that return A2UI surfaces

MCP servers built specifically for A2UI can attach application/a2ui+json UI resources to their tools or tool responses. When callMcpTool runs one of those tools, it fetches the UI resource and forwards the A2UI messages to the processor you passed to configureMcpCatalog. To build an MCP server that serves A2UI layouts, see Serve A2UI Layouts from an MCP Server.

Advanced configuration and troubleshooting

Expand any section below for multi-server routing, partial catalog registration, custom parsers, regular expression rules, and troubleshooting fixes:

Route tool calls across multiple MCP servers (configureMcpCatalog options)

A2UI payloads refer to tools by name only and never hardcode server URLs. If your host connects to multiple MCP servers, discover each server’s tools with listTools() at startup and route each toolName to the matching client inside getMcpClientForTool (which may also return a Promise):

You can call configureMcpCatalog again at any time to update individual options:

OptionTypePurpose
getMcpClientForTool(toolName: string) => McpToolClient | Promise<...>Returns the MCP client (Pick<Client, 'request' | 'readResource' | 'listTools'>) that handles toolName.
processorMessageProcessorReceives A2UI messages extracted from tool results and application/a2ui+json UI resources.
defaultVersionstringProtocol version stamped onto decoded tool-result messages that omit version (defaults to '1.0').
onMcpAppResource(payload: McpAppResourcePayload, context: DataContext) => voidOptional callback invoked when callMcpTool resolves a ui:// (text/html;profile=mcp-app) resource.
sandboxPartial<SandboxConfig>Overrides where /a2ui-sandbox/ is hosted (baseUrl, default '/a2ui-sandbox/') or its startup check (disableSecuritySelfTest).

If you serve the sandbox directory at a custom path or on a dedicated sandbox origin, set sandbox.baseUrl before rendering the first surface:

If getMcpClientForTool is not configured, McpApp dispatches allowed tool calls from the embedded widget as A2UI actions named after the tool, so a backend proxy agent can handle them through the MessageProcessor action callback.

Register only part of the catalog

If you want to expose McpApp and callMcpTool without the four data functions (or pick specific functions), derive a restricted catalog with mcpCatalog.withEntries and the individual *Implementation exports (CallMcpToolImplementation, TransformDataImplementation, UpdateDataModelImplementation, SplitImplementation, and RegexCaptureImplementation):

Add your own data-parsing functions

Every function in @a2ui/catalog-mcp must be implemented across every A2UI renderer, so the built-in function list stays small. If you need a specialized parser such as CSV, define it with createFunctionImplementation in your own catalog and register that catalog alongside mcpCatalog:

Payloads can then call parseCsv with "catalogId": "https://example.com/catalogs/parsers.json" and compose it with callMcpTool and transformData.

Regular expression rules in regexCapture

To keep payloads portable across web and native renderers, regexCapture accepts JavaScript regular expression syntax without lookahead or lookbehind assertions ((?=, (?!, (?<=, (?<!) and without backreferences (\1 through \9, \k<name>). It also rejects patterns vulnerable to catastrophic backtracking, using the same safety check as the basic catalog’s regex function. Unsupported or unsafe patterns throw an A2uiExpressionError.

Troubleshooting duplicate Lit or @a2ui/web_core packages

Loading two copies of lit or @a2ui/web_core breaks custom element registration and Catalog instance checks. Run npm dedupe (and check npm ls lit @a2ui/web_core), and in Vite add resolve: {dedupe: ['lit', '@a2ui/web_core']} to vite.config.ts.

Catalog schema

mcp_catalog.json

A2UI MCP Catalog — A2UI catalog for Model Context Protocol (MCP) integrations. It defines the `callMcpTool` function, the data functions that turn a tool result into data model updates, and the `McpApp` component that renders a sandboxed MCP App connected to the host through the MCP Apps bridge.
