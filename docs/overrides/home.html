01 · STATE-OF-THE-ART LLM GENERATION PERFORMANCE

Express: ~3x faster inference with an LLM-optimized format.

When you choose A2UI, you aren't signing up to make your LLM output verbose JSON. In A2UI, JSON is the universal wire interchange format that guarantees your agent and client renderers always stay compatible—while our Agent SDK lets you swap the inference format to match any model or latency budget.

77% smaller output with A2UI Express

A2UI Express strips away repeated keys, braces, and wrapper objects in favor of positional signatures—cutting output tokens by 55–70% across the spec and making GenUI fast even on small Gemma-class models.

Decoupled inference & wire formats

The Agent SDK compiles Express into standard A2UI v1.0 JSON before sending it over the wire. Your client renderers never see Express and never need updating when you tune prompts.

Swappable per model or use case

Use ExpressFormatFactory for maximum token speed, DirectJsonFormatFactory for chunk-by-chunk progressive JSON healing, or experimental Atom / Elemental formats.

02 · HYBRID SDUI + GEN UI WORKFLOWS

Macros: Give the model bigger words.

Asking an LLM to rebuild domain concepts out of raw Card, Row, and Text primitives every turn wastes tokens and causes visual drift across results. A2UI Macros let you write server code to define rich UI treatments with embedded data bindings, then give the LLM a simple, high-level call to instantiate them.

Domain nouns for the model

The model sees an Inference Catalog tailored to your domain (FlightCard, FareCompare, InvoiceSummary) with typed parameters instead of low-level layout boxes.

Expand to primitives on the server

MacroExpander compiles each macro call into standard primitive components (Card, Column, Row, Icon, Divider, Text) before sending over the wire.

Ship new UIs without App Store updates

Because macros expand into primitives your client already knows how to render, you can roll out brand-new domain UI treatments on the server with zero mobile binary releases.

1. Model Instantiates Macro Inference Catalog 
# The LLM writes one high-level call:
root = FlightCard(
  flight="OS 87",
  date="Mon, Dec 15",
  origin="Vienna",
  destination="New York",
  departs="10:15 AM",
  arrives="2:30 PM",
  status="On Time"
)

Simple inputs, zero layout drift: The LLM passes domain data without worrying about spacing, alignments, or divider placement.

2. Server Code Expands Treatment a2ui.transformers.macros 
@macro(description="Flight status card")
def flight_card(
  flight: str, date: str, origin: str,
  dest: str, departs: str,
  arrives: str, status: str
) -> Card:
  return Card(Column([
    Row([Icon("send"), Text(flight), Text(date)]),
    Row([Text(origin), Text("→"), Text(dest)]),
    Divider(),
    Row([Text(departs), Text(status), Text(arrives)]),
  ]))

Server-defined UI treatment: Automatically generates the JSON Schema for the LLM prompt and expands calls into flat primitives.

03 · FUTURE-PROOF ARCHITECTURE & GUARDRAILS

One environment handles prebuilt UIs, controlled generation, open-ended generation, and MCP apps.

A2UI is not just for open-ended generative UI. It is one protocol and one set of SDKs that lets you mix and match different approaches to agentic UI—providing the exact guardrails, determinism, or creative freedom each specific workflow requires.

Dial guardrails per screen

Use deterministic server-built cards for checkout, macro-constrained generation for search results, and open-ended primitive composition for long-tail queries.

Two-way MCP Apps integration

Host sandboxed ui:// MCP Apps inside an A2UI surface via catalogs/mcp, or ship interactive A2UI surfaces inside Claude, ChatGPT, and VS Code.

Future-proof renderer investment

Integrate A2UI renderers into your client app once. As your backend evolves from prebuilt templates to macros and full generative UI, your client code stays unchanged.
