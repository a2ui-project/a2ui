An A2UI Renderer SDK processes incoming A2UI messages on the client, maintains reactive state per surface, and renders catalog components through your application's UI framework. Official Renderer SDKs are available for Flutter, React, Lit, Angular, SwiftUI, and Android Jetpack Compose.

## Core SDK foundation

Every Renderer SDK builds on its language's Core SDK, which parses [wire messages](/concepts/messages/), maintains per-surface component and [`DataModel`](/concepts/data-binding/) state, evaluates data bindings, function calls, and string interpolation expressions, and validates schemas once per language. UI framework adapters focus on mapping resolved surface state to host UI components.

## Built-in Basic Catalog and custom catalogs

Official framework adapters include a built-in implementation of the [Basic Catalog](/concepts/catalogs/#the-basic-catalog) styled through the host framework's theming system (Material 3 on Flutter and Jetpack Compose, CSS custom properties on Web, and SwiftUI environment modifiers).

To render domain-specific UI, register a custom catalog with per-`Component` rendering logic and local functions under your `catalogId` (see [How to Define a Catalog](/guides/defining-a-catalog/)). Your components receive resolved properties and event callbacks while the Core SDK and adapter manage incremental updates and state bindings.

## What a Renderer SDK does

Each Renderer SDK abstracts `v0.9.1` and `v1.0` wire differences (plus `v0.8` on Web) behind a unified message processor and surface component:

1. Applies incremental [surface, component, and data model updates](/concepts/messages/), updating only changed subtrees so unchanged siblings keep focus and local UI state.
2. Evaluates [reactive data bindings](/concepts/data-binding/), nested `ChildList` lexical scopes, relative JSON Pointers, and local two-way input edits.
3. Executes [local catalog functions and reactive validation `checks`](/concepts/actions-and-functions/), plus `v1.0` caller and user-activation gates (`allowedCallers` and `requiresUserActivation`).
4. Builds capability and `sendDataModel` metadata payloads for your transport layer, dispatches user `action` events and structured `error` messages, and handles `v1.0` bidirectional function RPCs.
5. Maps protocol `AccessibilityAttributes` to host accessibility APIs (Flutter `Semantics`, Web WAI-ARIA, SwiftUI accessibility modifiers, and Jetpack Compose semantics).
