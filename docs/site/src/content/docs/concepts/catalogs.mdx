A catalog lists the components an agent can place on a surface, the functions that can run while the surface renders, and instructions that tell the LLM how to use both. The agent and the renderer work from the same catalog, so the agent only sends component types and properties that the renderer knows how to draw, never HTML, CSS, or scripts.

In the diagram below, the renderer tells the agent which catalogs it supports through `supportedCatalogIds`, and the agent picks one by setting `catalogId` in `createSurface`. The catalog has three parts. Components describe the UI building blocks: here, a custom `FlightStatusCard` with typed properties and an `allowedParents` rule, next to basic components such as `Column` and `Text`. Functions describe logic that runs on the renderer: `formatCurrency` runs while the renderer resolves a property, and `holdSeat` can only be called by the agent. Instructions are Markdown guidance that the agent SDK adds to the LLM's system prompt.

## Catalogs

Each catalog has a `catalogId`, which is usually a URI such as `https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json` or `https://example.com/catalogs/travel/v1/catalog.json`.

The same catalog document is used on both sides of the connection:

- **In the agent**, the agent SDK (`@a2ui/agent`, `a2ui-agent-sdk`, `a2ui_agent`) reads the component schemas, function signatures, and `instructions` to build the LLM system prompt, and validates the messages the LLM produces.
- **In the renderer**, the core SDK (`@a2ui/web_core`, `a2ui_core`, `A2UICore`) pairs each component schema with a native widget (a Flutter widget, a React, Angular, or Lit component, a SwiftUI view, or a Jetpack Compose composable) and each function signature with code that runs it.

## Components

Each entry in a catalog's `components` map is a JSON Schema that describes one component type. The schema uses these parts:

| Part               | How it is declared                                                      | What it does                                                                                                       |
| :----------------- | :---------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| Component type     | `"component": { "const": "FlightStatusCard" }`                          | Names the component type in the surface's flat component list.                                                     |
| Dynamic properties | `$ref` to `DynamicString`, `DynamicNumber`, `DynamicBoolean`, and so on | Accepts a literal value, a data binding (`@path`), or a function call (`@call`).                                   |
| Children           | `$ref` to `ComponentId` or `ChildList`                                  | Points to child components by ID, so the surface stays a flat list instead of a nested tree.                       |
| Placement rules    | `allowedParents`, `allowedChildren`                                     | Limits where the component can appear in the layout.                                                               |
| Validation         | `$ref` to `Checkable`                                                   | Adds a `checks` array of `{condition, message}` rules to an input.                                                 |
| Actions            | `$ref` to `Action`                                                      | Says what happens when the user interacts with the component: send an event to the agent or call a local function. |

<Aside>
  v0.9.1 catalogs use `path` and `call` instead of `@path` and `@call`. The rest of the component
  schema has the same shape.
</Aside>

This is a custom `FlightStatusCard` component in a v1.0 catalog:

```json
{
  "FlightStatusCard": {
    "type": "object",
    "description": "Shows a flight's number, fare, and action buttons.",
    "allowedParents": ["Column", "List"],
    "properties": {
      "component": {"const": "FlightStatusCard"},
      "flightNumber": {
        "$ref": "common_types.json#/$defs/DynamicString",
        "description": "IATA flight designator, such as 'NH 105'."
      },
      "fareAmount": {
        "$ref": "common_types.json#/$defs/DynamicNumber",
        "description": "Ticket fare in the booking currency."
      },
      "actions": {
        "$ref": "common_types.json#/$defs/ChildList",
        "description": "Buttons shown in the card footer."
      }
    },
    "required": ["component", "flightNumber"]
  }
}
```

## Functions

Catalog functions handle formatting, input validation, and boolean logic, and can also trigger side effects such as opening a URL. Each function declares a `returnType` (`"string"`, `"number"`, `"boolean"`, `"array"`, `"object"`, `"any"`, `"void"`, or, in v1.0, `"validationResult"`) and an `args` schema for its arguments.

### Who can call a function

The `allowedCallers` field controls whether the renderer, the agent, or both can run a function. The agent calls a renderer function by sending a `callRendererFunction` message.

| Setting                    | Who can call it                                                     | Typical uses                                                                               |
| :------------------------- | :------------------------------------------------------------------ | :----------------------------------------------------------------------------------------- |
| `"rendererOnly"` (default) | Only the renderer, while it resolves properties or handles actions. | Formatting (`formatCurrency`), validation (`required`, `regex`), and logic (`and`, `not`). |
| `"agentOnly"`              | Only the agent, through `callRendererFunction`.                     | Holding a seat, reading device state, or other work the agent asks the client to do.       |
| `"rendererOrAgent"`        | Both.                                                               | Calculations that both sides need, such as currency conversion.                            |

A function can also set `requiresUserActivation: true`. The renderer then runs it only in response to a user gesture, such as a button tap. Functions like `openUrl` use this so that an agent cannot open pages on its own.

<Aside type="caution">
  If a component calls a function that the renderer has not registered, the renderer sends the call
  to the agent as a `callAgentFunction` message. Register every local formatting and validation
  function in the renderer's catalog to avoid unexpected network round trips.
</Aside>

## Using a catalog in an agent

An agent loads a catalog from its JSON document and passes it to `A2uiGenerator` through a `CatalogConfig`. The generator uses the catalog to write the system prompt and to validate the LLM's output.

<Tabs syncKey="sdk-lang">
  <TabItem label="TypeScript">

```typescript
import {readFileSync} from 'node:fs';

import {A2uiGenerator, CatalogConfig, ExpressFormatFactory} from '@a2ui/agent';
import {Catalog} from '@a2ui/web_core';

const travelCatalog = Catalog.fromJson(JSON.parse(readFileSync('./catalogs/travel.json', 'utf8')));

const generator = new A2uiGenerator(
  [new CatalogConfig(travelCatalog)],
  undefined,
  new ExpressFormatFactory(),
);
```

  </TabItem>
  <TabItem label="Python">

```python
import json
from pathlib import Path

from a2ui.core import Catalog
from a2ui.inference_formats import ExpressFormatFactory
from a2ui.processor import A2uiGenerator, CatalogConfig

travel_catalog = Catalog.from_json(
    json.loads(Path("./catalogs/travel.json").read_text(encoding="utf-8"))

    catalogs=[CatalogConfig(catalog=travel_catalog)],
    inference_format_factory=ExpressFormatFactory(),
)
```

## Registering a catalog in a renderer

A renderer builds a `Catalog` that pairs each component schema with a native widget (a `ComponentImplementation`) and each function signature with code that runs it (a `FunctionImplementation`). It then passes the catalog to its message processor.

<Tabs syncKey="renderer-framework">
  <TabItem label="Flutter">

```dart
import 'package:a2ui_core/a2ui_core.dart';
import 'package:a2ui_flutter/a2ui_flutter.dart';
import 'package:flutter/material.dart';
import 'package:json_schema_builder/json_schema_builder.dart';

final flightStatusCard = ComponentImplementation(
  name: 'FlightStatusCard',
  schema: Schema.object(
    properties: {
      'component': Schema.string(enumValues: ['FlightStatusCard']),
      'flightNumber': CommonSchemasV1.dynamicString,
      'fareAmount': CommonSchemasV1.dynamicNumber,
    },
    required: ['component', 'flightNumber'],
  ),
  builder: (context, node, props, buildChild) {
    final flightNumber = props.string('flightNumber') ?? '';
    final fare = props.number('fareAmount') ?? 0;

    return Card(
      child: ListTile(
        leading: const Icon(Icons.flight_takeoff),
        title: Text('Flight $flightNumber'),
        trailing: Text('\$${fare.toStringAsFixed(2)}'),
      ),
    );
  },
);

final travelCatalog = Catalog<ComponentImplementation, FunctionImplementation>(
  id: 'https://example.com/catalogs/travel/v1/catalog.json',
  protocolVersion: A2uiProtocolVersion.v1_0,
  components: [flightStatusCard],
  functions: BasicCatalog.v1_0().functions.values.toList(),
);

final processor = MessageProcessor(catalogs: [travelCatalog]);
```

  </TabItem>

```tsx
import {Catalog} from '@a2ui/web_core';
import {BASIC_FUNCTIONS, DynamicNumberSchema, DynamicStringSchema} from '@a2ui/web_core/v1_0';
import {createComponentImplementation} from '@a2ui/react';
import {z} from 'zod';

const FlightStatusCardApi = {
  name: 'FlightStatusCard',
  allowedParents: ['Column', 'List'],
  schema: z.object({
    flightNumber: DynamicStringSchema,
    fareAmount: DynamicNumberSchema.optional(),
  }),
};

const FlightStatusCard = createComponentImplementation(FlightStatusCardApi, ({props}) => (
  <div className="flight-card">
    <strong>Flight {props.flightNumber}</strong>
    {props.fareAmount !== undefined && <span>${props.fareAmount.toFixed(2)}</span>}
  </div>
));

export const travelCatalog = new Catalog(
  'https://example.com/catalogs/travel/v1/catalog.json',
  '1.0',
  [FlightStatusCard],
  BASIC_FUNCTIONS,
);
```

## The basic catalog

A2UI publishes a basic catalog with 18 general-purpose components and 14 functions. The v1.0 version is [`catalogs/basic/v1/catalog.json`](https://github.com/a2ui-project/a2ui/blob/main/catalogs/basic/v1/catalog.json), and the v0.9.1 version is [`specification/v0_9_1/catalogs/basic/catalog.json`](https://github.com/a2ui-project/a2ui/blob/main/specification/v0_9_1/catalogs/basic/catalog.json).

- **Layout**: `Row`, `Column`, `List`, `Card`, `Tabs`, `Modal`, `Divider`
- **Display and media**: `Text`, `Image`, `Icon`, `Video`, `AudioPlayer`
- **Inputs**: `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `DateTimeInput`
- **Functions**: `formatString`, `formatNumber`, `formatCurrency`, `formatDate`, `pluralize`, `required`, `regex`, `length`, `numeric`, `email`, `openUrl`, `and`, `or`, `not`

You don't have to use the basic catalog. You can use it as is, restyle its components with your own design system, or replace it with a catalog built for your domain.
