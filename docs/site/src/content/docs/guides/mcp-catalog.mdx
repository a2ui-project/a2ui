import {Tabs, TabItem} from '@astrojs/starlight/components';

The `@a2ui/catalog-mcp` package connects A2UI v1.0 or later web surfaces directly to **[Model Context Protocol (MCP)](https://modelcontextprotocol.io/)** servers, letting UI components call MCP tools and embed sandboxed [MCP Apps](https://github.com/modelcontextprotocol/ext-apps) without waiting for another round-trip to the agent.

An MCP server exposes tools (functions like `list_issues` or `get_weather` that return data) and optional interactive HTML widgets. Once you register `mcpCatalog` in your Lit, React, or Angular app, your surfaces can:

1. Call MCP tools straight from buttons and inputs, then display the returned JSON or text right away.
2. Render interactive MCP Apps (such as a 3D canvas or a Kanban board) inside an isolated sandbox alongside native A2UI components.

---

## Quick setup

Setting up `@a2ui/catalog-mcp` takes three steps.

### Install the packages

Install `@a2ui/catalog-mcp` alongside `@a2ui/web_core`, `lit`, and the MCP TypeScript SDK:

```bash
npm install @a2ui/catalog-mcp @a2ui/web_core lit @modelcontextprotocol/sdk
```

`@a2ui/web_core` and `lit` are peer dependencies so your renderer and catalog share one copy of A2UI's core classes, and `@modelcontextprotocol/sdk` provides the MCP `Client` that connects to your server.

### Register the catalog in your app

Connect an MCP `Client` to your server, pass `mcpCatalog` alongside `basicCatalog` (or your own component catalog) to `MessageProcessor`, and call `configureMcpCatalog`:

<Tabs syncKey="web-framework">
  <TabItem label="Lit">

```ts
import {configureMcpCatalog, mcpCatalog} from '@a2ui/catalog-mcp';
import {basicCatalog, MessageProcessor} from '@a2ui/web_core/v1_0';
import {Client} from '@modelcontextprotocol/sdk/client/index.js';
import {StreamableHTTPClientTransport} from '@modelcontextprotocol/sdk/client/streamableHttp.js';

// 1. Connect to your MCP server.
const mcpClient = new Client({name: 'my-web-app', version: '1.0.0'});
await mcpClient.connect(new StreamableHTTPClientTransport(new URL('http://localhost:8000/mcp')));

// 2. Register mcpCatalog alongside basicCatalog.
const processor = new MessageProcessor([basicCatalog, mcpCatalog], action => {
  console.log('Action dispatched:', action);
});

// 3. Tell the catalog how to reach your MCP client and message processor.
configureMcpCatalog({
  getMcpClientForTool: () => mcpClient,
  processor,
});
```

  </TabItem>

`getMcpClientForTool` receives the name of the tool being called and returns the MCP client that executes it. When your app connects to one MCP server, return that client for every call; for multiple servers, see [Advanced configuration and troubleshooting](#advanced-configuration-and-troubleshooting).

### Share the catalog schema with your agent

Include the [MCP catalog schema](../../specification/v1.0/schemas/#mcp_catalog.json) in your agent setup so it knows how to emit MCP tool calls and `McpApp` components:

1. Load `@a2ui/catalog-mcp/catalog.json` (or [`catalogs/mcp/v1/catalog.json`](https://github.com/a2ui-project/a2ui/blob/main/catalogs/mcp/v1/catalog.json) on non-Node backends) alongside your component catalog when building your agent's prompt and schema validator.
2. Advertise the MCP catalog ID (`https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json`, exported as `mcpCatalog.id` and `MCP_CATALOG_ID`) in `supportedCatalogIds`. Calling `processor.getRendererCapabilities({versions: ['1.0']})` includes every registered catalog automatically.

You are ready to call MCP tools from your UI. If you also embed `McpApp` HTML widgets, complete the extra sandbox file step in [Embedding interactive MCP Apps](#embedding-interactive-mcp-apps).

## Calling MCP tools from your UI

An A2UI component can invoke an MCP tool when a user clicks a button or types into a field. Because the browser calls your MCP server through [`callMcpTool`](../../specification/v1.0/schemas/#mcp_catalog.json/functions/callMcpTool), the surface updates right away without another agent turn.

### Store tool output at a data path

The easiest way to call a tool is to pass `targetDataPath`. When the tool finishes, `callMcpTool` writes the response object to that path in the surface data model so your components can bind to it directly.

For example, this button action from [`mcp-json-tool-result.json`](https://github.com/a2ui-project/a2ui/blob/main/catalogs/mcp/v1/examples/mcp-json-tool-result.json) calls `list_issues` with the value at `/repository` and writes the response to `/issueResponse`:

```json
{
  "@call": "callMcpTool",
  "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
  "args": {
    "name": "list_issues",
    "arguments": {"repository": {"@path": "/repository"}},
    "targetDataPath": "/issueResponse"
  }
}
```

Components on the same surface (`"version": "1.0"`) can then bind to `/issueResponse/structuredContent/issues` (when the server returns structured content), `/issueResponse/json` (when the tool returns JSON text), or `/issueResponse/text` (for plain text).

<details>
<summary>Response object fields, error handling, and rapid-input protection</summary>

`callMcpTool` writes (and returns) an object with these fields:

| Field               | Contents                                                                                                                               |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------- |
| `structuredContent` | Structured data object returned by the MCP server, when the server includes one.                                                       |
| `json`              | Parsed JSON value when `text` is a JSON object or array (or an array of parsed JSON blocks when the tool returns several text blocks). |
| `text`              | All `text` content blocks from the tool result, joined with `\n`.                                                                      |
| `toolName`          | Name of the tool that ran.                                                                                                             |
| `toolInput`         | Resolved arguments sent to the tool.                                                                                                   |
| `toolResult`        | Raw MCP `CallToolResult` from the server.                                                                                              |

If a tool call fails or returns `isError: true`, `callMcpTool` throws an `A2uiExpressionError` and leaves the data model unchanged.

When several calls write to the same `targetDataPath` concurrently (such as a search box calling a tool as the user types), only the latest call writes its result. Slower responses from earlier calls are ignored so stale results never overwrite newer ones. Give each independent UI feature its own `targetDataPath` so unrelated calls do not cancel each other's writes.

</details>

### Filter and reshape JSON results

When an MCP tool returns more fields or rows than your UI needs, chain `callMcpTool` with `transformData` (a [JMESPath](https://jmespath.org/specification.html) query) and `updateDataModel`:

```json
{
  "@call": "updateDataModel",
  "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
  "args": {
    "updates": {
      "@call": "transformData",
      "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
      "args": {
        "jmespath": "{\"/issues\": json[?state == 'open'].{number: to_string(number), title: title}}",
        "data": {
          "@call": "callMcpTool",
          "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
          "args": {
            "name": "list_issues",
            "arguments": {"repository": {"@path": "/repository"}}
          }
        }
      }
    }
  }
}
```

Reading from the innermost call outward:

1. `callMcpTool` runs `list_issues` and returns the response object containing `json`.
2. `transformData` keeps only open issues, selects `{number, title}`, and wraps the result in `{"/issues": [...]}`.
3. `updateDataModel` writes `/issues` into the surface data model, updating any components bound to `/issues`.

Note that the rapid-input guard only applies to `targetDataPath` on `callMcpTool`, not to `updateDataModel`. For inputs that fire on every keystroke, bind directly to `targetDataPath`.

### Parse plain-text tool output

Some MCP servers return plain text meant for a language model (such as `Title: ...\nURL: ...` blocks) rather than JSON. The catalog includes `split` and `regexCapture` so an A2UI payload can extract rows and fields before passing them to `transformData` and `updateDataModel`, without adding per-tool parsing code to your host app. Your host app still chooses which MCP servers to connect through `getMcpClientForTool` (see [Quick setup](#quick-setup)). These built-in functions are most useful when users or admins configure that server list at runtime, such as in a chat app or playground. If your app only connects to one or two MCP servers that you control, writing a custom function in your own catalog is usually simpler (see _Add your own data-parsing functions_ under [Advanced configuration and troubleshooting](#advanced-configuration-and-troubleshooting)).

Here are the four data functions in `@a2ui/catalog-mcp`:

| Function          | Arguments            | What it does                                                                                                                         |
| :---------------- | :------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| `transformData`   | `jmespath`, `data`   | Evaluates a standard [JMESPath](https://jmespath.org/specification.html) query against `data` (returning `null` for missing fields). |
| `updateDataModel` | `updates`            | Writes each `{path: value}` pair in `updates` to the surface data model (`/` keys are absolute; others resolve relative to context). |
| `split`           | `value`, `separator` | Splits a string (or each item in an array of strings) by `separator`, or into individual characters when `separator` is `""`.        |
| `regexCapture`    | `value`, `pattern`   | Returns capture groups from the first match of `pattern` (or `null` if unmatched) for a string or each string in an array.           |

<details>
<summary>Example: parsing plain-text search results</summary>

In [`mcp-text-tool-result.json`](https://github.com/a2ui-project/a2ui/blob/main/catalogs/mcp/v1/examples/mcp-text-tool-result.json), a search tool returns text records separated by blank lines (`\n\n`), where each record starts with `Title: ...` and `URL: ...`. This chain splits the text into records, captures the title and URL from each record, drops non-matching header blocks (`[?@ != null]`), and writes the resulting array to `/results`:

```json
{
  "@call": "updateDataModel",
  "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
  "args": {
    "updates": {
      "@call": "transformData",
      "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
      "args": {
        "jmespath": "{\"/results\": [?@ != null].{title: [0], url: [1]}}",
        "data": {
          "@call": "regexCapture",
          "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
          "args": {
            "pattern": "^Title: (.*)\nURL: (.*)",
            "value": {
              "@call": "split",
              "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
              "args": {
                "separator": "\n\n",
                "value": {
                  "@call": "transformData",
                  "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
                  "args": {
                    "jmespath": "text",
                    "data": {
                      "@call": "callMcpTool",
                      "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
                      "args": {
                        "name": "tavily-search",
                        "arguments": {"query": {"@path": "/query"}}
                      }
                    }
                  }
                }
              }
            }
          }
        }
      }
    }
  }
}
```

</details>

### Tools that return A2UI surfaces

MCP servers built specifically for A2UI can attach `application/a2ui+json` UI resources to their tools or tool responses. When `callMcpTool` runs one of those tools, it fetches the UI resource and forwards the A2UI messages to the `processor` you passed to `configureMcpCatalog`. To build an MCP server that serves A2UI layouts, see [A2UI over MCP](../a2ui-over-mcp/).

## Embedding interactive MCP Apps

Some MCP servers provide interactive HTML widgets called [MCP Apps](https://github.com/modelcontextprotocol/ext-apps) for interfaces that go beyond standard form controls, such as a 3D canvas or a drag-and-drop Kanban board. The [`McpApp`](../../specification/v1.0/schemas/#mcp_catalog.json/components/McpApp) component runs those widgets inside a double-iframe sandbox and keeps their state in sync with your A2UI surface.

### Serve the sandbox files

`McpApp` loads its outer sandbox relay from `/a2ui-sandbox/` on your app's origin. Configure your bundler or web server to serve `node_modules/@a2ui/catalog-mcp/sandbox` at `/a2ui-sandbox/`:

<Tabs syncKey="bundler">
  <TabItem label="Vite">

Copy the folder into `public/a2ui-sandbox/`, or copy it at build time with [`vite-plugin-static-copy`](https://github.com/sapphi-red/vite-plugin-static-copy):

```ts
import {defineConfig} from 'vite';
import {viteStaticCopy} from 'vite-plugin-static-copy';

export default defineConfig({
  plugins: [
    viteStaticCopy({
      targets: [{src: 'node_modules/@a2ui/catalog-mcp/sandbox/*', dest: 'a2ui-sandbox'}],
    }),
  ],
});
```

  </TabItem>
  <TabItem label="Angular CLI">

Add the sandbox directory to the `assets` array in `angular.json`:

```json
{
  "glob": "**/*",
  "input": "node_modules/@a2ui/catalog-mcp/sandbox",
  "output": "a2ui-sandbox"
}
```

  </TabItem>
  <TabItem label="Static server">

Copy `node_modules/@a2ui/catalog-mcp/sandbox` to `<web root>/a2ui-sandbox` on the same origin as your app.

### Add McpApp to a surface

Place `McpApp` on an A2UI v1.0 surface with its HTML document (`htmlContent`), any surface data paths it shares (`data.paths`), and any MCP tools it is allowed to call (`allowedTools`):

```json
{
  "id": "scene3d_app",
  "component": "McpApp",
  "catalogId": "https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json",
  "title": "3D Holographic Geometry Studio",
  "allowedTools": ["capture_3d_snapshot"],
  "data": {
    "paths": {
      "scene3d": "/scene3d",
      "modelContext": "/scene3d/modelContext"
    }
  },
  "htmlContent": "<!doctype html><html><body>...<script>...</script></body></html>"
}
```

In this component, updates to `/scene3d` on the surface push into the widget, edits to `scene3d` inside the widget update sibling A2UI components, and tool calls outside `["capture_3d_snapshot"]` are blocked.

<details>
<summary>All <code>McpApp</code> component properties</summary>

An embedded `McpApp` is isolated from your page DOM, cookies, and browser storage, and interacts with your surface only through explicit properties:

| Property           | Required | Purpose                                                                                                                                             |
| :----------------- | :------- | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| `htmlContent`      | Yes      | HTML document of the app (values starting with `url_encoded:` are URL-decoded first).                                                               |
| `title`            | No       | Accessible title for the iframe (defaults to `"MCP App"`).                                                                                          |
| `data.paths`       | No       | Maps state keys inside the app (plus reserved `toolInput`, `toolResult`, and `modelContext` keys) to data model paths for two-way reactive sync.    |
| `allowedTools`     | No       | List of MCP tool names the app is allowed to call. Unlisted tool calls are rejected.                                                                |
| `allowedFunctions` | No       | Map of A2UI catalog function names to argument JSON Schemas that the app is allowed to invoke.                                                      |
| `csp`              | No       | Content Security Policy domain allowlists (`connectDomains`, `resourceDomains`, `frameDomains`, `baseUriDomains`) from the resource `_meta.ui.csp`. |
| `permissions`      | No       | Browser permissions (`camera`, `microphone`, `geolocation`, `clipboardWrite`) delegated from the resource `_meta.ui.permissions`.                   |

When a tool result returned by `callMcpTool` contains an MCP App `ui://` resource, its `resourceUri`, `html`, `csp`, and `permissions` fields are also included in the `callMcpTool` payload so you can bind `McpApp` properties to them.

</details>

`McpApp` starts at `500px` tall and resizes automatically when the embedded widget reports its content size. Customize the container with CSS custom properties on `a2ui-mcp-app` or any parent element:

```css

  --a2ui-sandboxed-frame-height: 400px;

  --a2ui-sandboxed-frame-border-radius: 12px;
  --a2ui-sandboxed-frame-background: #ffffff;
```

## Advanced configuration and troubleshooting

Expand any section below for multi-server routing, partial catalog registration, custom parsers, regular expression rules, and troubleshooting fixes:

<details>
<summary>Route tool calls across multiple MCP servers (<code>configureMcpCatalog</code> options)</summary>

A2UI payloads refer to tools by name only and never hardcode server URLs. If your host connects to multiple MCP servers, discover each server's tools with `listTools()` at startup and route each `toolName` to the matching client inside `getMcpClientForTool` (which may also return a `Promise`):

```ts
configureMcpCatalog({
  getMcpClientForTool: toolName => clientsByTool.get(toolName) ?? defaultClient,
  processor,
});
```

You can call `configureMcpCatalog` again at any time to update individual options:

| Option                | Type                                                             | Purpose                                                                                                                              |
| :-------------------- | :--------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| `getMcpClientForTool` | `(toolName: string) => McpToolClient \| Promise<...>`            | Returns the MCP client (`Pick<Client, 'request' \| 'readResource' \| 'listTools'>`) that handles `toolName`.                         |
| `processor`           | `MessageProcessor`                                               | Receives A2UI messages extracted from tool results and `application/a2ui+json` UI resources.                                         |
| `defaultVersion`      | `string`                                                         | Protocol version stamped onto decoded tool-result messages that omit `version` (defaults to `'1.0'`).                                |
| `onMcpAppResource`    | `(payload: McpAppResourcePayload, context: DataContext) => void` | Optional callback invoked when `callMcpTool` resolves a `ui://` (`text/html;profile=mcp-app`) resource.                              |
| `sandbox`             | `Partial<SandboxConfig>`                                         | Overrides where `/a2ui-sandbox/` is hosted (`baseUrl`, default `'/a2ui-sandbox/'`) or its startup check (`disableSecuritySelfTest`). |

If you serve the sandbox directory at a custom path or on a dedicated sandbox origin, set `sandbox.baseUrl` before rendering the first surface:

```ts
configureMcpCatalog({sandbox: {baseUrl: '/static/frames/'}});
```

If `getMcpClientForTool` is not configured, `McpApp` dispatches allowed tool calls from the embedded widget as A2UI actions named after the tool, so a backend proxy agent can handle them through the `MessageProcessor` action callback.

</details>

<details>
<summary>Register only part of the catalog</summary>

If you want to expose `McpApp` and `callMcpTool` without the four data functions (or pick specific functions), derive a restricted catalog with `mcpCatalog.withEntries` and the individual `*Implementation` exports (`CallMcpToolImplementation`, `TransformDataImplementation`, `UpdateDataModelImplementation`, `SplitImplementation`, and `RegexCaptureImplementation`):

```ts
import {CallMcpToolImplementation, mcpCatalog} from '@a2ui/catalog-mcp';

const mcpAppOnlyCatalog = mcpCatalog.withEntries(
  [...mcpCatalog.components.values()],
  [CallMcpToolImplementation],
);
```

</details>

<details>
<summary>Add your own data-parsing functions</summary>

Every function in `@a2ui/catalog-mcp` must be implemented across every A2UI renderer, so the built-in function list stays small. If you need a specialized parser such as CSV, define it with `createFunctionImplementation` in [your own catalog](../defining-a-catalog/) and register that catalog alongside `mcpCatalog`:

```ts
import {z} from 'zod';

import {mcpCatalog} from '@a2ui/catalog-mcp';
import {
  basicCatalog,
  Catalog,
  createFunctionImplementation,
  DynamicStringSchema,
  MessageProcessor,
} from '@a2ui/web_core/v1_0';

const ParseCsvImplementation = createFunctionImplementation(
  {
    name: 'parseCsv',
    returnType: 'any',
    schema: z.object({value: DynamicStringSchema}),
    description: 'Splits CSV text into rows of cells.',
  },
  ({value}) =>
    String(value)
      .split('\n')
      .map(line => line.split(',')),
);

const parsersCatalog = new Catalog(
  'https://example.com/catalogs/parsers.json',
  '1.0',
  [],
  [ParseCsvImplementation],
);

const processor = new MessageProcessor([basicCatalog, mcpCatalog, parsersCatalog], onAction);
```

Payloads can then call `parseCsv` with `"catalogId": "https://example.com/catalogs/parsers.json"` and compose it with `callMcpTool` and `transformData`.

</details>

<details>
<summary>Regular expression rules in <code>regexCapture</code></summary>

To keep payloads portable across web and native renderers, `regexCapture` accepts JavaScript regular expression syntax without lookahead or lookbehind assertions (`(?=`, `(?!`, `(?<=`, `(?<!`) and without backreferences (`\1` through `\9`, `\k<name>`). It also rejects patterns vulnerable to catastrophic backtracking, using the same safety check as the basic catalog's `regex` function. Unsupported or unsafe patterns throw an `A2uiExpressionError`.

</details>

<details>
<summary>Troubleshooting blank frames, rejected calls, and duplicate Lit packages</summary>

#### The McpApp frame stays blank (404 under /a2ui-sandbox/)

Check that `node_modules/@a2ui/catalog-mcp/sandbox` is served at `/a2ui-sandbox/` on your app's origin (see [Serve the sandbox files](#serve-the-sandbox-files)), or pass `configureMcpCatalog({sandbox: {baseUrl}})` with the path where you host those files.

#### Tool or function calls from an embedded McpApp are rejected

Check the browser console for warnings. Every MCP tool the widget calls must be listed in `allowedTools`, and every A2UI function must be listed in `allowedFunctions` and registered in `mcpCatalog` or the surface's catalog.

#### Custom element registration collisions or empty components

Loading two copies of `lit` or `@a2ui/web_core` breaks custom element registration and `Catalog` instance checks. Run `npm dedupe` (and check `npm ls lit @a2ui/web_core`), and in Vite add `resolve: {dedupe: ['lit', '@a2ui/web_core']}` to `vite.config.ts`.

</details>
