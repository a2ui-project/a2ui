01 · THE GENERATIVE UI SPECTRUM

No single Generative UI pattern fits every screen. A2UI gives you the entire spectrum.

Across production agentic apps, UI needs live along a spectrum—from full developer control over every pixel to full agent autonomy over the rendered surface. Picking a single band for your entire product is the most common architectural mistake. With A2UI, one protocol and one renderer investment covers every band.

◀ Fully Controlled · Developer Holds the Brush
Fully Open · Agent Owns the Canvas ▶

Band 2: Controlled Generative UI & Server Macros

Who Holds the Brush?

Developer defines pixel-perfect domain templates (@macro); the agent chooses which template fits the moment and populates typed parameters.

Best For

High-traffic, brand-critical surfaces (flight tickets, checkout cards, approval widgets) where predictability and zero layout drift are mandatory.

✓ Mix all 4 bands in a single conversation using the same A2UI wire protocol & client renderers.
Controlled GenUI with A2UI Server @macros Predictable · Zero Layout Drift

        Row([Icon("flight_takeoff"), Text(flight), Text(f"€{price_eur}")]),
        Row([Text(origin), Text("→"), Text(dest)]),
    ]))

03 · WHY A2UI?

Built for model speed, developer control, and native feel.

Other agent UI approaches force a painful trade-off: raw HTML/code generation is slow and unpredictable, while rigid tool-call cards lock you into a handful of hardcoded views. A2UI gives you all three advantages in one protocol.

PILLAR 01 · SWAPPABLE INFERENCE FORMATS

Decouple LLM token generation from the JSON wire contract.

Swap between JSON, A2UI Express, or custom formats in 1 line of SDK config.
What the LLM generates · A2UI Express Format 13 lines · 397 chars (−77%)

$/icon = "check"
$/title = "Enable notification"

title = Text($/title)
description = Text($/description, "body")

PILLAR 02 · SERVER-DEFINED @MACROS

Write rich UI treatments on the server; give the LLM a single domain call.

Ship new domain cards instantaneously without client binary updates.
1. MODEL WRITES MACRO Inference Catalog 
# High-level domain call:
root = FlightCard(
  flight="OS 87",
  date="Mon, Dec 15",
  origin="Vienna",
  dest="New York",
  departs="10:15 AM",
  arrives="2:30 PM",
  status="On Time"
)

Simple inputs, zero layout drift: The model passes domain arguments without inventing layout boxes.

2. SERVER EXPANDS @macro Decorator 
@macro(description="Flight status card")
def flight_card(
  flight: str, date: str, origin: str,
  dest: str, departs: str,
  arrives: str, status: str
) -> Card:
  return Card(Column([
    Row([Icon("send"), Text(flight)]),
    Row([Text(origin), Text("→"), Text(dest)]),
    Divider(),
    Row([Text(departs), Text(status)]),
  ]))

Server-defined UI treatment: Generates the LLM schema and expands calls into standard primitives.
