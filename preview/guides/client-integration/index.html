How to Integrate A2UI into a Client

Integrate an A2UI renderer into a Flutter, React, Lit, Angular, SwiftUI, or Jetpack Compose application using the Renderer SDKs to display interactive UIs from an AI agent and send user actions back.

If you are building the backend agent instead, see How to Integrate with My Agent Server. To register custom widgets beyond the built-in Basic catalog, see How to Define a Catalog and Authoring Universal Web Components.

Step 1: Install dependencies

Install the Renderer SDK and Core SDK packages for your target UI framework:

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Add the Swift packages to Package.swift (iOS 17+ / macOS 14+):

Add google() to your Gradle repositories and declare the androidx.a2ui dependencies in build.gradle.kts. 1.0.0-alpha02 currently targets A2UI v0.9.1 on the wire while v1.0 support is in progress:

Step 2: Initialize MessageProcessor

Create a MessageProcessor instance inside a session controller or service with the built-in Basic catalog and an action callback that forwards user events to the transport method you will add in Step 4.

The scope of the rendering session determines which surfaces the agent can modify. In a chat app, you can use one MessageProcessor per conversation to allow the agent to update or delete any surface in the conversation at any time by its surfaceId, or use one MessageProcessor per chat turn so the agent only modifies surfaces in the active turn and does not need unique surface IDs across turns. To register custom components or local functions alongside the Basic catalog, see How to Define a Catalog.

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Step 3: Mount surface views

Create a container view that subscribes to the active surfaces on MessageProcessor and renders an A2UI surface component for each one. Your container mounts new surfaces when createSurface arrives and unmounts them when deleteSurface arrives, while each mounted surface observes its own component tree and DataModel internally to update child components in place as updateComponents and updateDataModel messages arrive.

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Angular surface selector name

In @a2ui/angular, SurfaceComponent currently uses the <a2ui-v09-surface> selector for A2UI v1.0 surfaces (tracked in #4009). The unversioned <a2ui-surface> selector in @a2ui/angular/v0_8 belongs only to the legacy v0.8 renderer.

Step 4: Connect transport and handle actions

Add inbound and outbound transport methods to your session controller or service to decode incoming JSON payloads into MessageProcessor and send resolved action messages back to your agent. A2UI is transport-agnostic, so these methods can exchange messages over HTTP responses, Server-Sent Events (SSE), WebSockets, A2A, or MCP.

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Because 1.0.0-alpha02 targets A2UI v0.9.1, A2uiMessageParser expects one "version": "v0.9" (or "v0.9.1") JSON message object per call rather than a JSON array, with https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json and {"path": "..."} data bindings, and outbound envelopes set "version" to "v0.9":
Wire format: agent-to-renderer messages

Agents send createSurface followed by incremental updateComponents and updateDataModel messages, and remove finished surfaces with deleteSurface:

v1.0 agent_to_renderer.json ↗ v0.9.1 server_to_client.json ↗

  • v0.9.1
Wire format: outbound action message

When the user clicks Confirm order, MessageProcessor resolves context bindings against the surface DataModel and passes the action message to sendToAgent:

v1.0 renderer_to_agent.json ↗ v0.9.1 client_to_server.json ↗

  • v0.9.1

Step 5: Wire everything at the app entry point

Instantiate your session controller or service at the application entry point and pass its MessageProcessor to the surface container view from Step 3. Sharing this session connects user prompts and bidirectional agent messages to the rendered surfaces:

Additional steps

Customize Basic Catalog theme tokens on Web

Override the --a2ui-* CSS custom properties on :root or a container element to match your application’s theme, or apply the .a2ui-dark and .a2ui-light classes to lock a color scheme. Calling injectBasicCatalogStyles() in Step 2 adopts the default stylesheet into document.adoptedStyleSheets (and no-ops during server-side rendering):

In React, setMarkdownRenderer(renderMarkdown) from Step 2 configures the built-in Basic catalog Text elements; if your custom React catalog components call useMarkdownRenderer(), also wrap your tree in <MarkdownContext.Provider value={renderMarkdown}> from @a2ui/react.

Advertise renderer capabilities

Call getRendererCapabilities() on MessageProcessor and attach the result to your outbound transport metadata under a2uiRendererCapabilities so the agent knows which catalogs and protocol versions your client supports. If your team owns both the agent and the client app with a fixed catalog set, you can skip runtime negotiation and target those catalogs directly on the agent. Keep includeInlineCatalogs at its default false in production when the agent already holds matching catalogId schemas; set it to true only during prototyping when the agent accepts client-supplied inline schemas.

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Because 1.0.0-alpha02 targets A2UI v0.9.1, capabilities are advertised under a2uiClientCapabilities (keyed by "v0.9"):
Wire format: renderer capabilities metadata

buildCapabilitiesMetadata() produces the transport metadata envelope below ("1.0" in v1.0, "v0.9" in v0.9.1):

v1.0 renderer_capabilities.json ↗ v0.9.1 client_capabilities.json ↗
  • v1.0
  • v0.9.1

Synchronize client data models and forward RPCs

Call getRendererDataModel() on MessageProcessor and attach the returned snapshot under a2uiRendererDataModel in your outbound transport metadata alongside action messages and user prompts. MessageProcessor returns data models for active surfaces created with "sendDataModel": true, such as multi-field forms where local input edits update the client DataModel without firing separate action events.

If your catalogs use v1.0 remote agent functions (callAgentFunction) or agent-initiated client calls (callRendererFunction), pass outboundListener to MessageProcessor (processorOptions.outboundListener in Angular) to forward those envelopes through sendToAgent. To report malformed incoming payloads back to the agent as structured error messages instead of throwing exceptions, set reportErrorsOnly: true (paired with errorHandler on Web, or outboundListener on Flutter; SwiftUI and Jetpack Compose already emit validation errors on outboundListener and outboundEvents).

  • Flutter
  • React
  • Lit
  • Angular
  • SwiftUI
  • Jetpack Compose

Because 1.0.0-alpha02 targets A2UI v0.9.1, A2uiClientEventMessage.clientDataModel is populated automatically for sendDataModel = true surfaces and attached under a2uiClientDataModel:
Wire format: outbound action with data-model metadata

When the user triggers an action on a "sendDataModel": true surface, attaching buildDataModelMetadata() alongside message produces the transport envelope below:

v1.0 renderer_to_agent.json ↗ v1.0 renderer_data_model.json ↗ v0.9.1 client_to_server.json ↗ v0.9.1 client_data_model.json ↗
