Ecosystem Renderers & Tools

This page lists community renderers, agent libraries, and related projects built around the A2UI protocol.

Community maintenance

Third-party projects listed here are maintained by their respective authors and organizations, not by the core A2UI maintainers. Check each repository for license terms, protocol version support, and release status.

Official SDKs

For first-party SDKs maintained by the A2UI team, see the Agent SDKs guide (TypeScript, Python, Dart) and Renderer SDKs guide (Web with React, Lit, and Angular; Flutter; Swift; and Jetpack Compose), as well as the official @a2ui/react package.

Community showcase and contributing

The A2UI project welcomes community submissions and third-party tooling.

How to submit a project

Follow these steps to submit a renderer, library, or tool for inclusion in this directory:

  1. Create a fork of the a2ui-project/a2ui repository on GitHub.
  2. Sign the Google Contributor License Agreement if you have not already done so.
  3. Add your project row to docs/site/src/content/docs/ecosystem/renderers.mdx with package details, platform support, supported protocol versions, and repository links.
  4. Open a pull request against a2ui-project/a2ui with a description of the project and verification details or demo links.
  5. Share your project on GitHub Discussions with an optional demo video or walkthrough.

Listing criteria

Submissions are evaluated against the following guidelines:

  1. The project should have an open-source repository, typically licensed under Apache 2.0 or MIT.
  2. Documentation must explicitly state supported protocol versions (v0.8, v0.9 / v0.9.1, or v1.0).
  3. Client renderers should support core layout, text, input, and action components.
  4. The repository should include clear installation instructions and a minimal runnable example.
  5. Projects should reflect active maintenance. Projects that are no longer maintained should be marked as archived.

Code of conduct and participation

All community members and contributors are expected to follow Google’s Open Source Community Guidelines as described in CONTRIBUTING.md.

For discussions and general questions, participate in GitHub Discussions.

To report bugs or feature requests, use GitHub Issues.

To report security vulnerabilities, do not open a public issue. Follow the instructions in Google Vulnerability Reporting or contact the project maintainers privately.
