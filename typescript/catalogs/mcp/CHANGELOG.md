## Unreleased

- Add the `./v1_0` entry point with the A2UI v1.0 MCP catalog (`https://a2ui.org/specification/v1_0/catalogs/mcp/catalog.json`, bundled as `@a2ui/catalog-mcp/v1_0/catalog.json`), the `McpApp` universal component and `mcpCatalog`. `A2uiMcpApp` renders an MCP App's `htmlContent` inside the sandbox proxy and connects it to the surface through `McpAppBridge`, an `@modelcontextprotocol/ext-apps` `AppBridge` host: tool calls are limited to `allowedTools` and dispatched as `callMcpTool` actions, function calls are limited to `allowedFunctions` and validated against the declared JSON Schema before the catalog function runs, and `data.paths` bindings are pushed to the app once it is initialized and kept in sync in both directions. Denied and invalid calls answer with `McpError(InvalidParams)`, failures with `InternalError`. `@a2ui/catalog-mcp/v1_0/functions` exposes the v1 catalog id and functions without a DOM, reusing the root entry's implementations with A2UI messages found in tool results processed as `v1.0` messages unless they carry a version; `@a2ui/catalog-mcp/v1_0/components` exports the component and the bridge on their own. The `./v1_0` entry also exports the sandbox configuration (`configureSandbox`, `resolveSandboxUrl`, `DEFAULT_SANDBOX_BASE_URL`); the package ships the proxy pages in `sandbox/` and the host serves that directory itself. The root entry point and the v0.9 catalog are unchanged. [#2799](https://github.com/a2ui-project/a2ui/pull/2799)
- `createCallMcpToolImplementation` takes an optional `defaultVersion` option, the A2UI protocol version given to decoded messages that carry none. It defaults to `v0.9`, as before. [#2799](https://github.com/a2ui-project/a2ui/pull/2799)
- First publishable version, 0.1.0: the package is no longer private. `@a2ui/web_core` and `lit` become peer dependencies, `@modelcontextprotocol/ext-apps` is a new dependency and `@modelcontextprotocol/sdk` now requires `^1.29.0`. [#2799](https://github.com/a2ui-project/a2ui/pull/2799)
