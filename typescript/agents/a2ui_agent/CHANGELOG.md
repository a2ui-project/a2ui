## Unreleased

- **BREAKING**: A parser holds no state, and validation is separate from translation ([#3262](https://github.com/a2ui-project/a2ui/issues/3262), [#3263](https://github.com/a2ui-project/a2ui/issues/3263)). To migrate:
  1. `Parser.parseResponse(content, wrapped)` takes an options object: `parseResponse(content, {wrapped, state})`. It checks every message against the `RendererState` it is given, or a new, empty one, so an update to a surface the response does not create is now rejected unless the state holds the surface. A response is checked as a whole: a component may name a child that a later block adds, the trees of the surfaces it touches are checked once every block is applied, and the messages are applied to the state all or nothing. An error carries the parts read before it in `partialResults`.
  2. `Parser.parseChunk` and `Parser.parseStream`: open a stream with `parser.openStream({wrapped, state})` and pass each chunk to `feed(chunk)`, then call `close()`. The `ResponseStream` holds the buffers of one response and applies each message to its state as it emits it. `close` emits text held back as a possible tag, throws a `ParseError` if a block is still open, and checks the tree of an unwrapped stream. A stream that throws has ended.
  3. `Parser.compile` only translates a block into messages and reports what the notation gets wrong. To translate and check one block, call `parseResponse(block, {wrapped: false})`. A `Parser` subclass also implements the `catalogs` property.
  4. `DirectJsonStreamProcessorImpl`, `DirectJsonStreamProcessor`, `DirectJsonStreamProcessorFactory` and `DirectJsonStreamProcessorOptions` are removed. `DirectJsonParser(catalogs, {progressiveKeys})`, `DirectJsonFormat(catalogs, examples, {progressiveKeys})` and `DirectJsonFormatFactory({progressiveKeys})` take the keys whose string values a stream heals; the format's default is `['text']`, and the parser's is none. `DirectJsonResponseStream` is exported.
- Streamed Direct JSON follows `conformance/agent/direct_json/response_streaming.yaml`, as Python does, and every v0.9 and v1.0 case of it passes. A message is emitted as soon as it reads and the state accepts it, and again as it grows; a message that creates or deletes a surface is held until its object closes; no `loading_*` placeholder components are added; a message for a surface that does not exist yet is held back; text outside blocks is trimmed at its edges; and every streamed message gets the same checks as one in a whole response, with no option to skip them. The stream keeps no copy of surface state of its own: it reads surfaces, components and catalogs from its `RendererState`.
- `DirectJsonParser.unwrap` reads tags the way Python's does: a response without tags is one text part, a block still open at the end is a part that is not final, and tags may carry attributes. The Direct JSON parser reads blocks with a reader ported from Python's, which accepts trailing commas and raw line breaks inside strings, and reports a block that is not JSON as a `ParseError`.
- **BREAKING**: `A2uiRequestProcessor` no longer keeps a `MessageProcessor` for its whole life, so state no longer carries over between `parseResponse` calls by accident. Without a state, each call checks the response against a new one, as a chat agent wants. A canvas agent creates a state with `createState()` and passes it to `parseResponse` and `openStream`, or binds one with `new A2uiRequestProcessor(catalogs, examples, factory, {state})` or `A2uiGenerator.createProcessor(capabilities, factory, {state})`. A state that holds other catalogs than the processor is rejected with `A2uiCatalogError`. `A2uiRequestProcessor.parser` returns the one parser the processor reuses, and `openStream` reads a streamed response.
- **BREAKING**: Express output is checked against the catalogs and the surface trees like Direct JSON output, since the check moved from `DirectJsonParser.compile` to `Parser.parseResponse`. An Express block that assigns no `root` compiles to an `updateComponents`, which now needs a state that holds the surface.
- `A2uiGenerator.createProcessor` checks each example that is not text with `validatePayload`, instead of only checking that its component types exist.

- Add `RendererState`, the agent's mirror of the surfaces a renderer holds ([#3263](https://github.com/a2ui-project/a2ui/issues/3263)). It wraps one web_core `MessageProcessor`, created once with the linked catalogs, and checks each outbound message against everything applied before it. `apply(payload)` checks and applies messages atomically: if one is rejected, the state is left as it was. `transaction(fn)` extends that to everything `fn` applies. `checkTopology(surfaceIds)` checks that each surface has its root, that every reference resolves, and that every component added or replaced since the last check is reachable from the root. A component that an update leaves unreachable by rewriting its parent's children is accepted, since the protocol has no message that removes one component. An update to a surface the state never saw created is rejected, as a renderer rejects it. `RendererState`, `validatePayload` and the `SurfaceModel` type that `RendererState.getSurface` returns are exported from the package root.
- `validatePayload` runs the payload through a short-lived `RendererState` that assumes a surface the payload only updates already exists, instead of building a new `MessageProcessor` for the created surfaces and another for each candidate catalog of each updated surface. Its results are unchanged, except that a component of a created surface may now name a child that a later message of the same payload adds, as in Python.

- Catalogs with cross-catalog `$ref`s into peer catalogs work in prompts, compilation, decompilation and payload validation. `resolveCatalogs` returns per-request copies of the active catalogs linked to each other and to the registered catalogs (pristine and transformed), without changing the registered catalogs, and never links an inline catalog the agent refuses. `DirectJsonFormat`, `DirectJsonPromptGenerator`, `DirectJsonParser`, the Express schema helpers and payload validation likewise work with linked copies (see `linkCatalogs` in `@a2ui/web_core`) and leave the catalogs passed to them unchanged.
- `DirectJsonExamples` is exported from the package root. `DirectJsonPromptGenerator.generateExamples(catalog)` renders every turn when examples are an ordered list of turns, as Python does, instead of returning an empty string. `zod-to-json-schema` is no longer a dependency.
- Catalog providers load documents with `Catalog.fromJson`, the pruning transformers derive the pruned catalog with `Catalog.withEntries`, so it keeps the source catalog's document-level fields and its remaining entries, whose definitions its `toJson()` writes as loaded, recomputes the `anyComponent` and `anyFunction` unions and drops `$defs` that only pruned entries referenced, and `DirectJsonPromptGenerator` embeds the agent-to-renderer schema, the pruned `common_types` schema, and each active catalog's `Catalog.toJson()` document ([#3053](https://github.com/a2ui-project/a2ui/issues/3053)). Express reads component and function schemas from `Catalog.toJson()` instead of a copy of the loaded document kept beside the catalog, so it works with catalogs defined in code, such as the basic catalogs of `@a2ui/web_core`, and with pruned catalogs, and changes the caller makes to a document after loading it no longer reach Express ([#1626](https://github.com/a2ui-project/a2ui/issues/1626)).
- Initial implementation of `@a2ui/agent`, supporting A2UI protocol versions v0.9 and v1.0 and the Direct JSON and Express inference formats ([#2814](https://github.com/a2ui-project/a2ui/pull/2814), [#2916](https://github.com/a2ui-project/a2ui/pull/2916), [#2815](https://github.com/a2ui-project/a2ui/pull/2815)).
