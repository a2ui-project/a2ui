## Unreleased

- The Direct JSON and Express response parsers remove the backticks left at the edges of a block when a model writes the tags as inline code (`` `<a2ui>` ... `</a2ui>` `` or `` `<a2ui-json>` ... `</a2ui-json>` ``), drop text made of nothing but backticks, and in one-shot unwrapping (`unwrap` and `parseResponse`) recover at most one block closed with a closing tag when the model opened the block with a Markdown code fence or omitted the opening tag; `hasFormatContent` counts recovered blocks as complete format blocks.
- The Direct JSON and Express compilers strip stray unescaped line breaks inside JSON object keys and identifier/reference properties (`id`, `component`, `child`, `children` items, `surfaceId`, `catalogId`, and `componentId`, leaving user data under `updateDataModel` values untouched), at the edges of single-line Express strings, and inside Express data paths and line-wrapped identifiers (outside strings and comments, when the joined name resolves to a declared variable), accept SQL/Lua-style `--` comments in Express, and map a trailing numeric positional argument across optional enum properties when a component schema declares a single later numeric property.
- **Behavior change**: In Express, extra positional arguments beyond what the component schema accepts, and a numeric positional argument passed to an optional property that does not accept numbers (when no later single numeric property can be targeted), now throw `ExpressValidationError`.
- `ComponentPruningTransformer` and `FunctionPruningTransformer` now accept `null` for `allowedComponents` and `allowedFunctions` to prune all components or functions from a catalog, matching `[]` ([#3242](https://github.com/a2ui-project/a2ui/pull/3242)).
- **BREAKING**: `resolveCatalogs` and `A2uiGenerator.createProcessor` now accept the version-keyed renderer capabilities object sent by renderers (such as `{"v1.0": {"supportedCatalogIds": [...]}}`) directly without requiring callers to unwrap the version entry first, and throw `A2uiValidationError` when capabilities omit an entry for the registered catalogs' protocol version ([#3134](https://github.com/a2ui-project/a2ui/issues/3134), [#3219](https://github.com/a2ui-project/a2ui/issues/3219), [#3266](https://github.com/a2ui-project/a2ui/pull/3266)). Single unkeyed `RendererCapabilities` entries remain supported.
- **BREAKING**: `DirectJsonParser.unwrap` and `parseResponse` now return `[]` for an empty model response, a single text part for a plain-text response without `<a2ui-json>` tags, and the extracted payload for an unclosed `<a2ui-json>` block instead of throwing `ParseError`. Passing an empty string directly to `DirectJsonParser.compile` now throws `ParseError` ([#3314](https://github.com/a2ui-project/a2ui/pull/3314)).
