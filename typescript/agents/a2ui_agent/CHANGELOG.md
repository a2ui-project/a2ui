## Unreleased

- **BREAKING**: `A2uiGenerator` and `A2uiRequestProcessor` now default to `ExpressFormatFactory` instead of `DirectJsonFormatFactory`.
- Add `RendererState`, the agent's mirror of the surfaces a renderer holds ([#3263](https://github.com/a2ui-project/a2ui/issues/3263)). It wraps one web_core `MessageProcessor`, created once with the linked catalogs, and checks each outbound message against everything applied before it. `apply(payload)` checks and applies messages atomically: if one is rejected, the state is left as it was. `transaction(fn)` extends that to everything `fn` applies, and transactions nest. Rollback uses an undo log: each message records what it replaced (the components it adds or replaces, with a copy of the previous properties of a component updated in place, and the data model value at its path), and a failure reverts those records, latest first. A rollback leaves the state as it was, down to the order of each surface's components and of each data model object's keys, and a hole in a padded list stays a hole. A deleted surface is restored straight into the model, so each component keeps its own catalog and its place, and the data model keeps its root, whatever JSON value that is. If one undo fails, the others still run and the error that started the rollback propagates. No surface is copied when a message is applied or a transaction opens, so applying n messages to one surface takes time in proportion to n. When a JavaScript caller passes `transaction` a function that returns a promise, the transaction rolls back and throws `TypeError`, and until the promise settles the state takes no changes and handles the promise's rejection. Catalogs of a protocol version the state does not support, such as v0.8, are rejected with `A2uiCatalogError`. `checkTopology(surfaceIds)` checks that each surface has its root, that every reference resolves, and that every component added or replaced since the last check is reachable from the root. A component that an update leaves unreachable by rewriting its parent's children is accepted, since the protocol has no message that removes one component. An update to a surface the state never saw created is rejected, as a renderer rejects it. `RendererState`, `validatePayload` and the `SurfaceModel` type that `RendererState.getSurface` returns are exported from the package root.
- `validatePayload` runs the payload through a short-lived `RendererState` that assumes a surface the payload only updates already exists, instead of building a new `MessageProcessor` for the created surfaces and another for each candidate catalog of each updated surface. Its results are unchanged, except in three cases where it now accepts a payload it rejected, as Python does: a component of a created surface may name a child that a later message of the same payload adds; the tree of a surface that a later message of the same payload deletes is not checked, though each of its components still is; and a surface the payload updates, deletes and then creates again is taken to have existed before the payload, so the first update is accepted. It also accepts one message on its own, not only a list, as `RendererState.apply` does.
- `DirectJsonParser.compile` returns a block that holds one message on its own as a list of one message. Before, `validatePayload` rejected such a block with `Payload is not a JSON array.`
- `ComponentPruningTransformer` and `FunctionPruningTransformer` now accept `null` for `allowedComponents` and `allowedFunctions` to prune all components or functions from a catalog, matching `[]` ([#3242](https://github.com/a2ui-project/a2ui/pull/3242)).
- **BREAKING**: `resolveCatalogs` and `A2uiGenerator.createProcessor` now accept the version-keyed renderer capabilities object sent by renderers (such as `{"v1.0": {"supportedCatalogIds": [...]}}`) directly without requiring callers to unwrap the version entry first, and throw `A2uiValidationError` when capabilities omit an entry for the registered catalogs' protocol version ([#3134](https://github.com/a2ui-project/a2ui/issues/3134), [#3219](https://github.com/a2ui-project/a2ui/issues/3219), [#3266](https://github.com/a2ui-project/a2ui/pull/3266)). Single unkeyed `RendererCapabilities` entries remain supported.
- **BREAKING**: `DirectJsonParser.unwrap` and `parseResponse` now return `[]` for an empty model response, a single text part for a plain-text response without `<a2ui-json>` tags, and the extracted payload for an unclosed `<a2ui-json>` block instead of throwing `ParseError`. Passing an empty string directly to `DirectJsonParser.compile` now throws `ParseError` ([#3314](https://github.com/a2ui-project/a2ui/pull/3314)).
