## Unreleased

## 0.0.2

- Added `Skill`, `SkillSet`, and `SkillGenerator` to generate `SKILL.md` packages from inference formats and component catalogs.
- The Express compiler keeps a map literal as written, quoted keys or not, when one of its keys shares a name with an Express construct (`variable`, `path`, `call`, `check`, `skipped`); before, such a map was read as a variable reference, data binding, function call or check, and lost its data ([#3410](https://github.com/a2ui-project/a2ui/issues/3410)). A `_` anywhere but in place of an argument now throws `ExpressValidationError`.
- The Express compiler finds a data binding inside a map literal given to a property that does not admit one even when the map has keys named `event`, `functionCall` or `@call`, and throws `ExpressForbiddenDatabindingError`. A `__proto__` key in an `Event` context is kept as data, and a `__proto__` keyword argument is reported as an unknown property rather than dropped.
- An Express variable is looked up among the variables the block assigns only, so a name such as `toString` is not resolved through `Object.prototype`, and a variable named `__proto__` is kept as a variable. A variable whose value refers back to it, directly or through other variables, throws `ExpressValidationError` rather than `RangeError`. Only a `$path` given to a component property, directly or through variables, is passed to the component's checks; a map literal shaped like a data binding is data and is not.
- In v1.0 the Express decompiler reads only `@call` as a function call, so an object with plain `call` and `args` keys is written as a map literal. An object with the version's binding key beside other keys is also written as a map literal rather than as a data binding that drops the other keys.
- Express number literals follow the same grammar as the core `${...}` expression parsers: an optional sign (`+3`, `-1`), a leading or trailing dot (`.5`, `1.`) and an exponent (`1e-7`, `2.5E+3`) are now accepted. A literal outside the double range (such as `1e999`) throws `ExpressParseError`. **BREAKING**: `ExpressDecompiler` writes numbers as ECMAScript `Number.prototype.toString` does (`1e-7`, `0.000015`, `1e+21`), writes negative zero as `-0.0`, and throws `A2uiValidationError` for `Infinity` and `NaN` where it used to write them as text that no Express compiler reads back ([#3019](https://github.com/a2ui-project/a2ui/issues/3019)).
- The Direct JSON and Express response parsers remove the backticks left at the edges of a block when a model writes the tags as inline code (`` `<a2ui>` ... `</a2ui>` `` or `` `<a2ui-json>` ... `</a2ui-json>` ``), drop text made of nothing but backticks, and in one-shot unwrapping (`unwrap` and `parseResponse`) recover at most one block closed with a closing tag when the model opened the block with a Markdown code fence or omitted the opening tag; `hasFormatContent` counts recovered blocks as complete format blocks.
- The Direct JSON and Express compilers strip stray unescaped line breaks inside JSON object keys and identifier/reference properties (`id`, `component`, `child`, `children` items, `surfaceId`, `catalogId`, and `componentId`, leaving user data under `updateDataModel` values and `createSurface.dataModel` untouched), at the edges of single-line Express strings, and inside Express data paths and line-wrapped identifiers (outside strings and comments, when the joined name resolves to a declared variable), accept SQL/Lua-style `--` comments in Express, and map a trailing numeric positional argument across optional enum properties when a component schema declares a single later numeric property.
- **BREAKING**: In Express, extra positional arguments beyond what the component schema accepts, and a numeric positional argument passed to an optional property that does not accept numbers (when no later single numeric property can be targeted), now throw `ExpressValidationError`.
- **BREAKING**: Express `IDENTIFIER` and `CHECK` tokens now follow UAX 31 (`[\p{XID_Start}_] [\p{XID_Continue}]*`) rather than ASCII-only letters, digits, and underscores. In `ExpressDecompiler`, non-identifier component IDs before protocol v1.0 (such as `title-heading`) and reserved-word component IDs in any version (`true`, `false`, `null`, `_`) are written with a derived variable name and `id="..."` so they round-trip; from v1.0 onward, component IDs that are not valid UAX 31 identifiers throw `A2uiValidationError`. `ExpressInvalidIdentifierError` has been removed ([#3390](https://github.com/a2ui-project/a2ui/issues/3390)).
- **BREAKING**: `A2uiGenerator` and `A2uiRequestProcessor` now default to `ExpressFormatFactory` instead of `DirectJsonFormatFactory`.
- **BREAKING**: A parser holds no state, and validation is separate from translation ([#3262](https://github.com/a2ui-project/a2ui/issues/3262), [#3263](https://github.com/a2ui-project/a2ui/issues/3263)). To migrate:
  1. `Parser.parseResponse(content, wrapped)` takes an options object: `parseResponse(content, {wrapped, state})`. It checks every message against the `RendererState` it is given, or a new, empty one, so an update to a surface the response does not create is now rejected unless the state holds the surface. A response is checked as a whole: a component may name a child that a later block adds, the trees of the surfaces it touches are checked once every block is applied, and the messages are applied to the state all or nothing. An error carries the parts read before the failing block in `partialResults`, or only the text when the tree check fails, since that check spans every block; none of them is applied to the state.
  2. `Parser.parseChunk` and `Parser.parseStream`: open a stream with `parser.openStream({wrapped, state})` and pass each chunk to `feed(chunk)`, then call `close()`. The `ResponseStream` holds the buffers of one response and applies each message to its state as it emits it. `close` emits text held back as a possible tag, throws a `ParseError` if a block is still open, and checks the tree of an unwrapped stream. A stream that throws has ended.
  3. `Parser.compile` only translates a block into messages and reports what the notation gets wrong. To translate and check one block, call `parseResponse(block, {wrapped: false})`. A `Parser` subclass also implements the `catalogs` property.
  4. `DirectJsonStreamProcessorImpl`, `DirectJsonStreamProcessor`, `DirectJsonStreamProcessorFactory` and `DirectJsonStreamProcessorOptions` are removed. `DirectJsonParser(catalogs, {progressiveKeys})`, `DirectJsonFormat(catalogs, examples, {progressiveKeys})` and `DirectJsonFormatFactory({progressiveKeys})` take the keys whose string values a stream heals; the format's default is `['text']`, and the parser's is none. `DirectJsonResponseStream` is exported.
- Streamed Direct JSON follows `conformance/agent/direct_json/response_streaming.yaml`, as Python does, and every v0.9 and v1.0 case of it passes. A message is emitted as soon as it reads and the state accepts it, and again as it grows; only `updateComponents` and `updateDataModel` are emitted while they grow, and any other message, such as `createSurface`, `deleteSurface` or `callRendererFunction`, is held until its object closes; no `loading_*` placeholder components are added; a message for a surface that does not exist yet is held back; text outside blocks is trimmed at its edges; and every streamed message gets the same checks as one in a whole response, with no option to skip them. The stream keeps no copy of surface state of its own: it reads surfaces, components and catalogs from its `RendererState`. A stream reads each chunk once, so it takes time in proportion to the response: the scan for the close tag and the read of the open block go on where the previous chunk left them, a message that has closed is not read or checked again, and a growing `updateComponents` is checked for the components it adds and a growing `updateDataModel` for the lists and maps its value gains. Streaming 400 components in 40-character chunks took 7.0 s before and 0.13 s now. The timing suites `conformance/agent/direct_json/scaling.yaml` and `conformance/agent/express/scaling.yaml` run with `yarn test:timing`, and in CI.
- `DirectJsonParser.unwrap` reads tags the way Python's does: a response without tags is one text part, a block still open at the end is a part that is not final, and tags may carry attributes. The Direct JSON parser reads blocks with a reader ported from Python's, which accepts trailing commas and raw line breaks inside strings, and reports a block that is not JSON as a `ParseError`.
- **BREAKING**: `A2uiRequestProcessor` no longer keeps a `MessageProcessor` for its whole life, so state no longer carries over between `parseResponse` calls by accident. Without a state, each call checks the response against a new one, as a chat agent wants. A canvas agent creates a state with `createState()` and passes it to `parseResponse` and `openStream`, or binds one with `new A2uiRequestProcessor(catalogs, examples, factory, {state})` or `A2uiGenerator.createProcessor(capabilities, factory, {state})`. A state that holds other catalogs than the processor is rejected with `A2uiCatalogError`. `A2uiRequestProcessor.acceptsState` tells whether a state holds the processor's catalogs, treating a v0.9 and a v0.9.1 catalog with the same id as the same catalog, as `RendererState` does, so an agent that keeps a state per conversation can tell when to make a new one. `A2uiRequestProcessor.parser` returns the one parser the processor reuses, and `openStream` reads a streamed response.
- **BREAKING**: Express output is checked against the catalogs and the surface trees like Direct JSON output, since the check moved from `DirectJsonParser.compile` to `Parser.parseResponse`. An Express block that assigns no `root` compiles to an `updateComponents`, which now needs a state that holds the surface.
- `A2uiGenerator.createProcessor` checks each example that is not text with `validatePayload`, instead of only checking that its component types exist.
- Add `RendererState`, the agent's mirror of the surfaces a renderer holds ([#3263](https://github.com/a2ui-project/a2ui/issues/3263)). It wraps one web_core `MessageProcessor`, created once with the linked catalogs, and checks each outbound message against everything applied before it. `apply(payload)` checks and applies messages atomically: if one is rejected, the state is left as it was. `transaction(fn)` extends that to everything `fn` applies, and transactions nest. Rollback uses an undo log: each message records what it replaced (the components it adds or replaces, with a copy of the previous properties of a component updated in place, and the data model value at its path), and a failure reverts those records, latest first. A rollback leaves the state as it was, down to the order of each surface's components and of each data model object's keys, and a hole in a padded list stays a hole. A deleted surface is restored straight into the model, so each component keeps its own catalog and its place, and the data model keeps its root, whatever JSON value that is. If one undo fails, the others still run and the error that started the rollback propagates. No surface is copied when a message is applied or a transaction opens, so applying n messages to one surface takes time in proportion to n. When a JavaScript caller passes `transaction` a function that returns a promise, the transaction rolls back and throws `TypeError`, and until the promise settles the state takes no changes and handles the promise's rejection. Catalogs of a protocol version the state does not support, such as v0.8, are rejected with `A2uiCatalogError`. `checkTopology(surfaceIds)` checks that each surface has its root, that every reference resolves, and that every component added or replaced since the last check is reachable from the root. A component that an update leaves unreachable by rewriting its parent's children is accepted, since the protocol has no message that removes one component. An update to a surface the state never saw created is rejected, as a renderer rejects it. `markChecked(surfaceIds)` stops holding the components each surface changed against later `checkTopology` calls: a stream that fails after emitting messages, and a block cut off at the end of a response, mark their surfaces checked, since the renderer holds those components and no message removes one. Dangling references and a missing root are still reported. `RendererState`, `validatePayload` and the `SurfaceModel` type that `RendererState.getSurface` returns are exported from the package root.
- `validatePayload` runs the payload through a short-lived `RendererState` that assumes a surface the payload only updates already exists, instead of building a new `MessageProcessor` for the created surfaces and another for each candidate catalog of each updated surface. Its results are unchanged, except in three cases where it now accepts a payload it rejected, as Python does: a component of a created surface may name a child that a later message of the same payload adds; the tree of a surface that a later message of the same payload deletes is not checked, though each of its components still is; and a surface the payload updates, deletes and then creates again is taken to have existed before the payload, so the first update is accepted. It also accepts one message on its own, not only a list, as `RendererState.apply` does.
- `DirectJsonParser.compile` returns a block that holds one message on its own as a list of one message. Before, `validatePayload` rejected such a block with `Payload is not a JSON array.`
- `ComponentPruningTransformer` and `FunctionPruningTransformer` now accept `null` for `allowedComponents` and `allowedFunctions` to prune all components or functions from a catalog, matching `[]` ([#3242](https://github.com/a2ui-project/a2ui/pull/3242)).
- **BREAKING**: `resolveCatalogs` and `A2uiGenerator.createProcessor` now accept the version-keyed renderer capabilities object sent by renderers (such as `{"v1.0": {"supportedCatalogIds": [...]}}`) directly without requiring callers to unwrap the version entry first, and throw `A2uiValidationError` when capabilities omit an entry for the registered catalogs' protocol version ([#3134](https://github.com/a2ui-project/a2ui/issues/3134), [#3219](https://github.com/a2ui-project/a2ui/issues/3219), [#3266](https://github.com/a2ui-project/a2ui/pull/3266)). Single unkeyed `RendererCapabilities` entries remain supported.
- **BREAKING**: `DirectJsonParser.unwrap` and `parseResponse` now return `[]` for an empty model response and a single text part for a plain-text response without `<a2ui-json>` tags, instead of throwing `ParseError`. `unwrap` returns the extracted payload of an unclosed `<a2ui-json>` block as a part that is not final; `parseResponse` still rejects such a block with `ParseError`, since the response ended before the block did. Passing an empty string directly to `DirectJsonParser.compile` now throws `ParseError` ([#3314](https://github.com/a2ui-project/a2ui/pull/3314)).
