## Unreleased

- Add `RendererState`, the agent's mirror of the surfaces a renderer holds ([#3263](https://github.com/a2ui-project/a2ui/issues/3263)). It wraps one web_core `MessageProcessor`, created once with the linked catalogs, and checks each outbound message against everything applied before it. `apply(payload)` checks and applies messages atomically: if one is rejected, the state is left as it was. `transaction(fn)` extends that to everything `fn` applies, and transactions nest. Rollback uses an undo log: each message records what it replaced (the components it adds or replaces, with a copy of the previous properties of a component updated in place, and the data model value at its path), and a failure reverts those records, latest first. A deleted surface is restored by replaying it through the processor, so each component keeps its own catalog. No surface is copied when a message is applied or a transaction opens, so applying n messages to one surface takes time in proportion to n. `checkTopology(surfaceIds)` checks that each surface has its root, that every reference resolves, and that every component added or replaced since the last check is reachable from the root. A component that an update leaves unreachable by rewriting its parent's children is accepted, since the protocol has no message that removes one component. An update to a surface the state never saw created is rejected, as a renderer rejects it. `RendererState`, `validatePayload` and the `SurfaceModel` type that `RendererState.getSurface` returns are exported from the package root.
- `validatePayload` runs the payload through a short-lived `RendererState` that assumes a surface the payload only updates already exists, instead of building a new `MessageProcessor` for the created surfaces and another for each candidate catalog of each updated surface. Its results are unchanged, except that a component of a created surface may now name a child that a later message of the same payload adds, as in Python. It also accepts one message on its own, not only a list, as `RendererState.apply` does.
