# **Angular Framework Adapter Codebase Blueprint**

## **Architecture & Ecosystem Map**

The Angular adapter (`@a2ui/angular`) rendering visual components and universal W3C Custom Elements dynamically, built on `@a2ui/web_core` and `@a2ui/web_core/universal` with root entry point `src/index.ts` (`ng-package.json`) and versioned subpaths for v0.9 (`src/v0_9`, including `src/v0_9/testing`) and legacy v0.8 (`src/v0_8`).

- **Native Signal Reactivity (`initializeAngularReactivity`, `ComponentBinder`)**: Internal `initializeAngularReactivity` (`src/core/reactivity.ts`, called by `provideA2Ui`, `A2uiRendererService`, and `ComponentBinder`) plugs Angular's `signal`, `computed`, and `effect` primitives into `@a2ui/web_core` via `setSignalImplementation`. `ComponentBinder` binds resolved `ComponentNode.props` (`binder.bindNode(node)`) into `BoundProperty<T>` signals; `binder.bind(context)` is retained as a `@deprecated` compatibility path per [a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md) and reads `@checks` on v1.0+ versus `checks` below v1.0.
- **Surface & Host Resolution (`SurfaceComponent`, `ComponentHostComponent`, `SurfaceNodeResolver`)**: `SurfaceComponent` (`a2ui-v09-surface`) provides a per-surface `SurfaceNodeResolver` owning a `NodeResolver` and mounts a root `ComponentHostComponent` (`a2ui-v09-component-host`). `ComponentHostComponent` mounts native Angular components (including `toWebComponent`-wrapped `<a2ui-ng-*>` entries even when `useUniversalComponents` is enabled) via `NgComponentOutlet`, mounts real universal Web Component entries as custom elements when `useUniversalComponents` is enabled, and hands `A2UI_ELEMENT_CONNECTED_EVENT` to each entry's optional `onElementConnected(element, context, injector)` callback.
- **Universal Custom Elements (`AngularWcHost`, `toWebComponent`, `AngularCatalog`)**: `toWebComponent` wraps Angular catalog components into lazy `a2ui-ng-<name>` `AngularWcHost` subclasses (and `AngularCatalog` auto-attaches lazy wrappers to plain `{...api, component}` entries) accepting `el.node` (`el.context` is `@deprecated` and retained per [a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md)) so Angular components and Lit Web Components interleave. `AngularWcHost` resolves its `Injector` in order: explicit `el.injector`, nearest DOM ancestor in `hostInjectors`, owning `SurfaceGroupModel` in `surfaceGroupInjectors`, then the active fallback stack (`activeInjectors`).
- **Host accessibility (`src/core/accessibility.ts`)**: `ComponentHostComponent` (for a native Angular component) and `AngularWcHost` call `bindHostAccessibility` from `@a2ui/web_core/universal`. Each provides its own `A2UI_ACCESSIBILITY_TARGETS`, which `AccessibilityTargetDirective` (`[a2uiAccessibilityTarget]`) and `ValidationErrorsDirective` (`[a2uiValidationErrors]`) fill with the elements the component marks.
- **Basic Catalog & Conformance (`src/basic-catalog.ts`, `src/v0_9/`, `karma.conf.js`)**: Root `BasicCatalog` (`protocolVersion: '1.0'`) wraps `@a2ui/web_core/catalogs/basic/v1` universal elements with `UniversalOnlyComponent`, paired with `provideA2UI` (defaulting `useUniversalComponents` to `true`); `src/v0_9` ships native Angular basic catalog components (`protocolVersion: '0.9'`). Karma runs `src/adapter_conformance.spec.ts` (`conformance/core/accessibility.yaml`, `conformance/core/adapter_conformance.yaml`, `conformance/adapter/adapter_conformance_v0_9.yaml`) and `src/e2e_scenarios.spec.ts` (recursive `conformance/e2e/**/*.yaml`).

## **Local Technical Decisions & Overrides**

- **OnPush & Signal-Driven Change Detection**: Uses `ChangeDetectionStrategy.OnPush` and Angular Signals across all host and catalog components.
- **Surface entry point & DI (`src/core/surface.component.ts`, `src/core/a2ui-renderer.service.ts`, `src/basic-catalog.ts`)**: Deliberate compatibility override: `SurfaceComponent` accepts `surfaceId` (`string`) and optional `dataContextPath` (default `'/'`) instead of `SurfaceModel` directly, and components retrieve `SurfaceModel` through `A2uiRendererService.surfaceGroup.getSurface(surfaceId)` rather than an ambient `SurfaceModel` DI token so existing Angular template bindings stay intact. `provideA2UI` omits `provideEnvironmentInitializer` for `initializeAngularReactivity` (unlike `provideA2Ui`), relying on `A2uiRendererService` or `ComponentBinder` construction (removal condition: attach `provideEnvironmentInitializer` in `provideA2UI` if reactivity must initialize before either service is injected). Pre-existing gap: `SurfaceComponent` hardcodes root component ID `'root'` instead of reading `surface.rootId` (removal condition: resolve the surface's `rootId`, defaulting to `'root'`, instead of passing a literal `'root'`).
- **Markup-only Markdown (`src/core/markdown.ts`, `src/core/a2ui-renderer.service.ts`, holds `module_blueprint_commit` at `b1dd6507`)**: `MarkdownRenderer.render(markdown, options?)` returns `Promise<string>`, and `provideMarkdownRenderer` accepts only an optional markup-returning function (`MarkdownRendererFn`, defaulting to `DefaultMarkdownRenderer`; bridged to `@a2ui/web_core/universal`'s `setMarkdownRenderer` only when `useUniversalComponents` is enabled and `MarkdownRenderer` is provided, and bound via `[innerHTML]` in native v0.9 `TextComponent`), not a framework-native Angular component or `TemplateRef` view ([a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md) §4.1 in `2e3d9bc4`). Removal condition: add Angular-native Markdown view support (including placeholder mounting inside universal `Text`) before advancing `module_blueprint_commit` past `b1dd6507`.
- **Injector lookup & synchronous teardown (`src/catalog/angular_wc_host.ts`)**: Deliberate override: resolves DI through injector registries (`hostInjectors`, `surfaceGroupInjectors`, `activeInjectors`) rather than a portal-based per-surface `HostRegistry`, letting Angular's `createComponent` attach views straight into each custom element while preserving enclosing injector lookup. Pre-existing gap (present in `b1dd6507` and `0d70f440`): `disconnectedCallback()` destroys `componentRef` synchronously instead of keeping mounted state across a same-task DOM move ([universal_custom_elements.blueprint.md](../../../../features/universal_custom_elements.blueprint.md) §5). Removal condition: defer `componentRef` teardown to the end of the task so a same-task reconnect retains the mounted component.
- **Extension metadata wiring (`src/core/component-host.component.ts`, `src/catalog/angular_wc_host.ts`, `src/catalog/to_web_component.ts`, departs from `9055207b`)**: `componentApiFields` preserves static `api.metadata`, `CatalogComponent` exposes `metadata` and computed `extensions`, and `ComponentHostComponent` passes `metadata` only when `acceptsMetadata()` is true. However, `ComponentHostComponent.setupAngularComponent` creates an eager `webCoreEffect` on `node.metadata` calling `cdr.markForCheck()` on metadata-only updates even when `acceptsMetadata()` is false (and for `CatalogComponent` subclasses that inherit `metadata` without reading it), and `AngularWcHost` neither watches `node.metadata` in `subscribeToNode` nor calls `setInput('metadata', ...)` in `updateContext()`, so Angular components inside universal containers do not receive `metadata` ([a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md) §3 in `9055207b`, the next unmet module commit after `2e3d9bc4`). Removal condition: avoid subscribing to `node.metadata` or calling `cdr.markForCheck()` for views that do not read metadata (including `CatalogComponent` subclasses that leave `metadata` unread), and forward reactive `metadata` in `AngularWcHost` only when the mounted component accepts it.
- **Host accessibility pre-1.0 fallback scope (`typescript/core/web_core/src/universal/host_accessibility.ts`, departs from `24d1bf9c`)**: `resolveAccessibilityProps` iterates `['@accessibility', 'accessibility']` without inspecting protocol version, so on a v1.0 component that declares a custom object-valued `accessibility` property and omits `@accessibility`, `ComponentHostComponent`, `AngularWcHost`, and every `A2uiLitElement` subclass (custom universal elements and `BasicCatalogA2uiLitElement` alike) treat that property as protocol accessibility attributes ([a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md) §3 and [universal_custom_elements.blueprint.md](../../../../features/universal_custom_elements.blueprint.md) §5/§7 in `24d1bf9c`). Removal condition: limit the bare `accessibility` fallback to pre-1.0 surfaces in `resolveAccessibilityProps` and pass surface protocol version from its callers (`bindHostAccessibility`, `A2uiLitElement.updated`).
- **Unresolved placeholders without `fallbacks` API (`src/core/surface.component.ts`, `src/core/component-host.component.ts`, `renderA2uiNode`, `A2uiLitElement.renderNode`, holds `universal_custom_elements` at `0d70f440`)**: `SurfaceComponent` and `ComponentHostComponent` use `display: contents` hosts, render nothing for `pending`, `unknown-type`, and `cyclic` nodes without re-reporting to the surface error channel (conforming to `28f0a416`; local `console.error` / `console.warn` output lives in `reportUnresolved`), and native v0.9 `ListComponent` hides empty wrappers via `data-a2ui-empty`. Neither `SurfaceComponent` / `ComponentHostComponent` nor `@a2ui/web_core/universal`'s `renderA2uiNode` / `A2uiLitElement.renderNode` implements the `fallbacks` API (`TemplateRef` with `{$implicit: info}`, `parentComponentType`, `fallbackContext`, or a per-surface fallback renderer) from `32c03e3a`. Removal condition: implement `fallbacks` across `SurfaceComponent`, `ComponentHostComponent`, `renderA2uiNode`, `A2uiLitElement.renderNode` (passing `{surface, parentComponentType}` without returning early on pending children), and the adapter's per-surface fallback renderer registration, then advance `universal_custom_elements` past `0d70f440`. Commit `32c03e3a` also adds §4.4 Fallbacks to [a2ui_framework_adapter.blueprint.md](../../../../modules/a2ui_framework_adapter.blueprint.md), so it remains unmet for `module_blueprint_commit` until then.
